# Проектная практика Python и PHP

В веб-приложении откройте **Проекты** или **Профессии → Python/PHP → Открыть
проекты**. В соответствующих главах программы также есть ссылки на практику.

| Профессия | Проект | Что делает ученик |
|---|---|---|
| Python | Менеджер задач | Функции, проверка ввода, неизменяемые обновления, JSON |
| Python | От CSV к отчёту | pandas, очистка данных, группировка, matplotlib |
| Python | Веб-приложение заметок | Flask, JSON API, SQLite, экранирование HTML |
| Python | Первая нейросеть на PyTorch | PyTorch на CPU, классификация Iris, обучение, сохранение весов |
| PHP | Корзина интернет-магазина | Типизированный класс, суммы в копейках, проверки ввода |
| PHP | Учёт расходов на PDO | PDO SQLite, подготовленные запросы, агрегирование |
| PHP | JSON API каталога | HTTP-методы, маршрутизация, JSON, коды ответа |
| PHP | Мини-приложение MVC | Разделение модели и представления, поиск, HTML |

Названия в интерфейсе задаются в `server/practice_projects/`. Каждый проект
содержит стартовые файлы с `TODO(human)`, три последовательных этапа и
накопительные проверки: новый этап проверяет и предыдущие требования.
Всего восемь проектов и 24 этапа. Это первый набор больших практических работ;
он ещё не покрывает все главы профессий, Django, tkinter, Laravel и Symfony.

## Работа ученика

- Файлы и вложенные папки создаются на странице; код редактируется в Monaco.
  Основная точка входа — `main.py` или `main.php`.
- Изменения сохраняются автоматически. Проект принадлежит текущему аккаунту.
  Конфликт двух вкладок не перезаписывает чужую версию. Локальный черновик
  помогает восстановиться после потери связи; при конфликте его можно скачать.
- **Версии** возвращают одно из десяти предыдущих сохранений. **Проект** скачивает
  ZIP с исходниками и папками для продолжения работы на своём компьютере.
- **Запустить** выполняет точку входа; **Проверить этап** запускает проверки.
  Для завершения этапа нужны успешная проверка текущей версии и объяснение
  ученика длиной от 30 символов. Качество объяснения автоматически не оценивается.
- Наставник видит текущий код, задание, последний результат запуска, историю
  общения и релевантные фрагменты уже проиндексированной базы знаний. Используется
  выбранная для пользователя модель проверки ответов. Подсказка, объяснение,
  разбор кода и полное решение — отдельные режимы. Правки можно просмотреть
  перед применением; изменившийся после ответа проект не заменяется старой правкой.

Для доступности RAG загрузите источники Python/PHP через настройки базы знаний.
Отсутствие документов не мешает наставнику отвечать на основе задания и кода.
Файлы проекта отправляются настроенному провайдеру модели при обращении к наставнику.

## Подключение среды запуска

Без исполнителя доступны редактор, сохранения, ZIP и наставник. Для запуска нужен
отдельный Linux Docker Engine и доверенный worker. Основной сервер AI Anki сам
пользовательские программы не исполняет; небезопасного локального fallback нет.

Для локальной установки с Docker Compose из корня репозитория:

```bash
# Сохраните значение в своём менеджере секретов/окружении развёртывания.
export AI_ANKI_PRACTICE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"

# Собрать приложение, worker и три окружения. Первый запуск скачивает большие образы.
docker compose -f docker-compose.yml -f docker-compose.practice.yml --profile practice-images build

# Профиль нужен только для сборки образов, а не для обычного запуска сервисов.
docker compose -f docker-compose.yml -f docker-compose.practice.yml up -d ai-anki practice-worker
```

В PowerShell токен можно задать через `$env:AI_ANKI_PRACTICE_TOKEN`; обе команды
Compose остаются теми же. Docker Desktop должен использовать Linux containers.
Не сохраняйте токен в Git. Веб-приложению и worker требуется одинаковое значение,
не короче 32 символов.

Проверка соединения из контейнера приложения:

```bash
docker compose -f docker-compose.yml -f docker-compose.practice.yml exec ai-anki python -c 'import os, requests; r=requests.get(os.environ["AI_ANKI_PRACTICE_WORKER"]+"/health", headers={"Authorization":"Bearer "+os.environ["AI_ANKI_PRACTICE_TOKEN"]}, timeout=10); print(r.status_code, r.text)'
```

`/health` подтверждает доступность Docker, но не наличие всех runtime-образов.
После сборки выполните пробный запуск каждого типа окружения. Незавершённый
стартовый проект должен показать обычную ошибку `TODO`/`NotImplementedError`,
а не ошибку отсутствующего Docker-образа.

На TrueNAS замените первый compose-файл на `docker-compose.truenas.yml` и
выполняйте команды из каталога клона репозитория. Overlay использует этот
каталог как build context для worker и runtime-образов.

Для публичной установки используйте выделенную VM/хост для student-контейнеров.
На нём соберите runtime-образы и запустите worker; основному приложению задайте
`AI_ANKI_PRACTICE_WORKER` с приватным адресом worker и общий токен. При переходе
между хостами используйте защищённую приватную сеть либо HTTPS. API worker не
предназначен для прямого доступа из браузера или открытого Интернета.
Worker запускается также командой:

```bash
uvicorn server.practice_worker:create_app --factory --host 127.0.0.1 --port 8091
```

Ему нужны зависимости сервера и Docker CLI с доступом к своему daemon.
Compose-overlay монтирует Docker socket **только в worker**. Это привилегированный
доступ к хосту, поэтому совместное размещение с приложением — вариант для
доверенной локальной установки, не полноценная граница безопасности для публичного
сервиса. Предпочтителен [rootless Docker](https://docs.docker.com/engine/security/rootless/)
на выделенном хосте. Путь сокета можно передать через `AI_ANKI_DOCKER_SOCKET`.

## Ограничения и результаты

Один запуск получает новый контейнер без сети и без файлов/секретов сервера:
непривилегированный UID, read-only root, удалённые capabilities,
`no-new-privileges`, стандартный Docker seccomp, 1 CPU и 64 процесса.

| Окружение | Время программы | Память | Библиотеки |
|---|---:|---:|---|
| Python / PHP | 60 с | 384 МиБ | Flask, pytest; PHP CLI + PDO SQLite |
| Python data | 60 с | 768 МиБ | pandas, NumPy, matplotlib, scikit-learn |
| Python ML | 180 с | 1536 МиБ | Всё выше + CPU PyTorch |

Workspace и `/tmp` — отдельные tmpfs по 64 МиБ. Вывод ограничен 64 КиБ.
По умолчанию worker допускает два параллельных запуска; переменная
`AI_ANKI_PRACTICE_PARALLEL` принимает значения от 1 до 4. Один пользователь
может иметь один активный запуск. Контейнер удаляется после выполнения/остановки;
при аварии worker его основная команда завершится через 300 секунд.
Завершённые результаты worker хранятся в памяти не более часа до следующей очистки;
приложение сохраняет последние 12 запусков каждого проекта в `data/practice.db`.

Сохраняются исходники (до 64 текстовых файлов суммарно 512 КБ), история,
общение и результаты проверок. Файловая система запуска временная: изменения,
сделанные программой, автоматически не попадают обратно в редактор. Для скачивания
результатов пишите их в `artifacts/`: до восьми обычных файлов, не более 1 МБ каждый
и 2 МБ суммарно; разрешены HTML, JSON, CSV, TXT, PNG, PT, SQLite.

Предпросмотр Flask/MVC — **HTML-снимок ответа последнего запуска** в sandbox iframe.
Формы и скрипты отключены; постоянно работающего веб-сервера, интерактивного HTTP
preview, терминала, установки произвольных pip/Composer-пакетов и GUI tkinter
в этой версии нет. Flask проверяется через настоящий `test_client`; PHP API —
через диспетчер запросов. Скачанный PHP API содержит HTTP entrypoint для локального
сервера, но учебный массив товаров пока живёт только в рамках одного запроса.

Проверки предназначены для обучения, не для защищённой экзаменационной аттестации:
код ученика и проверки выполняются внутри одного контейнера. Они не влияют
на существующие сертификаты профессий. База `practice.db` и локальные черновики
не содержат Docker-токен или ключи модели; включите базу в обычные резервные копии.

## Проверки разработчика

```bash
python -m unittest discover -s tests -p 'test_practice.py' -v
python -m unittest discover -s tests -p 'test_practice_solutions.py' -v
cd web && npm run build
```

Второй набор исполняет только написанные в репозитории эталонные примеры. Ему
нужны Flask, pandas, matplotlib, scikit-learn, torch и PHP с PDO SQLite;
путь к PHP можно задать через `AI_ANKI_TEST_PHP`. При отсутствии библиотек
соответствующие проверки пропускаются. Он не включает исполнение ученического
кода на хосте приложения.

Unit-тесты проверяют изоляцию пользователей, конкурирующие сохранения, этапы,
снимки, ZIP, контекст наставника, аргументы Docker, тайм-аут, лимит вывода и
остановку. Реальный Docker smoke-тест обязателен при развёртывании: Windows-среда,
в которой добавлен модуль, не имела установленного Docker.
